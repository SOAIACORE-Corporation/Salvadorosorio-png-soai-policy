# SOAIACORE Azure Provider Pilot P0

This directory is the minimum, disposable Azure binding for Architecture v0.6 FINAL/FROZEN. It keeps PostgreSQL plus `pgvector` as canonical memory, Blob Storage as canonical evidence bytes, and runs Core, Web, and Worker in MOCK mode. It does not create Kubernetes, Kafka, GPU, a graph database, a separate vector database, or permanent environment tiers.

The effective live topology and production deltas are captured in
`docs/azure/SOAIACORE_ARCHITECTURE_v0.6-R2_AZURE_P0_AS_IS_2026-08-25.md`.

P0-07 was applied after the authorized P0-06 GO decision. The live pilot is in
P0-08 observation and remains bounded by its explicit expiry and teardown
contract. This configuration is not a production pattern.

## Validated scope and operating constraints

- Region: `eastus2`, subject to subscription-specific quota and SKU availability at the authorized plan/apply time.
- Container Apps: Workload Profiles environment with the default Consumption profile; Core and Web scale from zero to one replica, and Worker is a manually triggered job.
- PostgreSQL: Flexible Server 17, Burstable `B_Standard_B1ms`, 32 GiB (`P4`), seven-day backup retention, no high availability, no geo-redundant backup, private network only. The `azure.extensions` allowlist enables `vector`; migrations remain responsible for `CREATE EXTENSION vector`.
- Evidence: private Hot-tier StorageV2 Blob container with Standard LRS.
- Registry: GHCR remains private. Core, Web, and Worker use Azure Container Apps registry credentials (`ghcr.io`, GitHub username, and a `password_secret_name`) with the three exact approved digest references. No ACR is created.
- Secrets: the GHCR pull token is a short-lived PAT classic with `read:packages` only. It is supplied outside Git as sensitive Terraform input and stored as an Azure Container Apps secret separately on Core, Web, and Worker. The PostgreSQL password remains generated by Terraform and passed as an application secret. Both values are sensitive in local Terraform state under the approved P0-only local-state exception; state and plan files are operator-restricted and sanitized after teardown.
- Identity: one user-assigned workload identity and one GitHub branch-scoped OIDC deployer identity. No client secret is created.
- Observability: one Log Analytics workspace with 30-day retention.
- Provider registration is set to `none`; planning must not silently register Azure resource providers.

## P0 168-hour cost envelope

The recalculated public-list-price envelope is **USD 3.82-20.28 for 168
hours**, with `COST_MODE=ZERO_FIRST`. The lower bound assumes Core and Web
scale to zero outside validation windows, one short Worker execution, minimal
Blob and Log Analytics use, and eligibility for the Container Apps monthly free
grant. The upper bound allows materially longer active validation windows,
additional log ingestion, storage operations, DNS queries, and modest network
transfer without changing the P0 resource envelope.

The fixed compute basis is PostgreSQL Flexible Server B1ms at USD 12.41 per
730-hour month, or approximately USD 2.86 for 168 hours. The remaining lower
bound covers the 32-GiB P4 storage and low-volume supporting services. Actual
charges can vary by subscription agreement, offer, billing currency, free-grant
consumption elsewhere in the subscription, runtime seconds, operations, log
ingestion, and transfer. This is a deployment gate estimate, not a price quote.

## Static validation and read-only plan

Use Terraform 1.15.x. Keep real `.tfvars`, plan files, and state outside Git.

```powershell
terraform fmt -check
terraform init -backend=false
terraform validate
terraform plan -out=p0.tfplan -var-file=pilot.tfvars
```

Before planning, set `TF_VAR_ghcr_token` in the operator process from the
approved secret source. Never place the token on the command line, in a tracked
file, or in captured logs. `ghcr_username` may be supplied in the ignored pilot
tfvars file. The token owner must have read access to the three private packages
and the PAT classic must be limited to `read:packages` (and authorized for SSO
when the organization requires it).

`terraform plan` requires valid Azure authentication, the target subscription ID supplied outside source control when it cannot be inferred, three approved image references, and an explicit RFC3339 `expires_at`. It is read-only with respect to Azure; it writes only local Terraform working data and the requested local plan file.

## Teardown contract

The owner must run the following against the same protected state no later than `expires_at`:

```powershell
terraform destroy -var-file=pilot.tfvars
```

Before destroy, export only evidence/database data that an approved retention policy requires. After destroy, verify the resource group is absent and record the result in the P0 teardown receipt. The resource group is the containment boundary; the TTL tag is evidence and scheduling input, not an Azure-native automatic deletion mechanism.
